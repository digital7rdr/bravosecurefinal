> _"Not all organization must show when I open 1 organization inside of Channels."_ · _"You must only be able to see or create new organizations here [the Workspaces hub]. Once you enter the organization, you don't see anything about other organisations."_

## 2. Design decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Why                                                                                                                                                                                                                                                                                                          |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | **The workspace context is PERSISTED, per user.** `activeWorkspace` becomes a `persist` store on `@store/debouncedJsonStorage` (N-persist) holding `{user_id, org_id, name, role}`; a hydrated value whose `user_id` is not the signed-in user is ignored; `clearActiveWorkspace()` (sign-out, `authStore.ts:682`) also purges the persisted value. Validation stays where it is: the navigator's two-strike reconcile ejects a context the server no longer lists, and the server scopes every read by membership anyway (a stale orgId reads EMPTY, never another tenant).                                                                                                                                      | R3. The store's "session-only is safer" argument was written before the reconcile existed; today a stale context degrades to an empty directory for one refresh and then the ejection card. Persisting is what makes "remembered from last time" true after a restart, a notification tap or a drawer entry. |
| D2  | **ONE entry resolver** `resolveWorkspaceEntry(user, persisted)` (pure, `src/store/workspaceEntry.ts`): persisted valid → keep (name/role refreshed); else exactly ONE enterable affiliation → adopt it; else ZERO enterable affiliations → null and the legacy single-org behaviour (an agency person's channels are one org by construction); else (≥ 2, nothing remembered) → null **and the surface renders the picker gate**. Run by `DepartmentalNavigator` once `user.workspaces` is defined (an old server that omits the array = legacy behaviour, untouched). "Enterable affiliation" = `user.workspaces[]` ∪ `user.org` when it is an AGENCY org (not in `workspaces` by construction) ∪ `managed_org`. | R3. The null state stops meaning "all organisations". Belt (the navigator resolves) and braces (§D3) — the vs2 lesson: a fix that is right at one layer is defeated one layer out.                                                                                                                           |
| D3  | **No surface renders a cross-org channel list.** `DepartmentChannelsScreen`, `DepartmentalHomeScreen`'s channel list and the vault company shelf render a **"Choose a workspace"** gate (one card, `navigateOnce` to `WorkspaceHub`) whenever `activeCtx == null && enterableAffiliations.length >= 2`; with ≤ 1 they behave exactly as today. `orgSectionsOf` and the per-org headers STAY (B-624 containment for old servers / mixed rows) but become unreachable for a multi-org user.                                                                                                                                                                                                                         | R2. ## 5. Edge cases (initial — the edge-case agent extends)

1. Persisted context for a workspace the user was removed from while the app was closed → scoped read returns EMPTY (membership join), two-strike reconcile ejects → the ejection card, then the hub. Never another tenant's data.
2. Account switch on one device → `user_id` mismatch on hydrate → ignored; sign-out purges.
3. `user.workspaces` arrives AFTER the surface mounts (cold start): the gate must not flash for a single-workspace user — render a neutral loading state while `workspaces === undefined` on a NEW server (distinguish "old server" = the field never arrives, from "not loaded yet" = `user` itself not hydrated).
4. Owner whose own workspace is ACTIVE and who is also a member elsewhere → ≥ 2 → gate/picker; owner tile "Owner · Manage and enter" exists already.
5. Lapsed owner with other memberships → D6 card + the other tiles; their own channels are not in the directory (Q1) but their chats remain in the messenger list.
6. Agency manager/CPO who owns a personal workspace → `user.org` (agency) + 1 workspace → ≥ 2 → gate; the hub shows the workspace tile + the agency card (D4) → entering the agency sets a `manager`/`cpo` context; D5 keeps it from being ejected.
7. A push for org B's channel while the persisted context is A: the agency shell adopts B (existing); the client/CPO shells open the CHAT (not the directory) — the edge agent verifies where each lane lands and that no lane lands on the directory with the wrong org.
8. A deep link (`DepartmentChannels`) with a persisted context → scoped to it; with none and ≥ 2 → the gate.
9. `useDeptUnread` with a null context and ≥ 2 → keeps today's cross-org sum on the tab badge (a count, not a list; the hub dot map is cross-org on purpose).
10. Two workspaces with the same name → the hub's A7 disambiguator already handles the picker.
