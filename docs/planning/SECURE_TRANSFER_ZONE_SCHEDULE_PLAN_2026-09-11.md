## 5. Edge cases (initial — the edge-case agent extends)

1. Pin inside two overlapping bboxes (none today; AE and ZA are disjoint) → first match, documented.
2. Device far from every zone (a traveller): the picker's initial centre = the device fix if inside a zone, else the last zone / AE; the derivation only runs on a CONFIRMED pin.
3. Drop-off in another zone than the pick-up → the zone follows the PICK-UP (the server prices by pickup); the drop-off picker keeps refusing out-of-zone pins relative to the derived zone.
4. Ops board `transfer_min_lead_hours` = 3 h → the on-demand window collapses; the pill reads "Scheduled" for everything ≥ 3 h and the earliest slot = +3 h.
5. Pro "now-only" rule (`proNowOnlyBooking`): a Pro user picking a far date → derived `later` — verify whether Pro must stay `now` (a server rule?) and, if so, clamp the picker for Pro with copy.
6. A stale bbox mirror (ops moved a region box): the server refuses `pickup_outside_region` with `pickup_region` → the client adopts it, re-estimates, and tells the user.
7. DST/offset: the earliest slot and the derived mode are computed in the ZONE's clock (`zone_utc_offset_hours`) — pin.
