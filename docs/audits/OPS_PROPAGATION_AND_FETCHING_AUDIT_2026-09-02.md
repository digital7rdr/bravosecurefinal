## 0. The two answers in one paragraph each

**A — "OK or not?"** Every ops write lands on the server correctly (role-gated, audited, idempotency-keyed; the B-721 scale work is intact). What is NOT ok is the read side: there is **no invalidation channel of any kind** — no WS/FCM "config changed" event, no cluster-wide cache bust for pricing or tiers — so each value reaches the app by a different accident of TTLs and screen-mount timing. The killswitch reflects in ≤2 s; a **price change takes up to 60 s per server pod and pods disagree in that window**; a **tier/comp grant is refused by Pro-gated endpoints for up to 30 s**; and two things **never reflect without a new app build**: a newly added region (the client iterates a compiled 2-entry list) and any **region-specific price** (the app's display endpoint always returns the GLOBAL board while the charge path uses the region board — display ≠ charge). A further set of money/dispatch parameters is env-only and not ops-changeable at all. Table in §1, ranked mechanisms in §2, the not-changeable list in §3.

**B — "Industry standard?"** The HTTP wrapper is: typed client, cookie session + CSRF double-submit, silent token refresh, idempotency keys, correct 401/403 semantics, `no-store` on admin data, mapbox code-split, encrypted IndexedDB (AES-GCM-256, PBKDF2 600k). The **strategy layer above it is not**: a 100% client-side, polling-only SWR app with **no global `SWRConfig`**, **no stale-while-revalidate UX** (`keepPreviousData` never set → every filter/tab/keystroke blanks the table), **client-side search over a server-limited window** (returns "no results" for real rows), **cursor pagination on 1 list of ~30**, **two lists that silently truncate**, **duplicate polling of the same endpoints under different keys** (~2 req/s per open tab), **one unbounded SQL query polled console-wide**, no optimistic updates, no virtualization, no `AbortController`, no skeletons/toasts, no freshness indicator, and no ops websocket (OC-08, still open). Scorecard in §4, ranked gaps in §5.

## 2. Why it "takes some time to reflect" — ranked by mechanism

1. **OP-01 · P1 · Region price overrides never reach the app, and display ≠ charge.** `GET /bookings/service-pricing` → `pricing.config()` (GLOBAL); `booking.service.ts` charges `config(regionFromPickup)`. The console shows the regional number, the app quotes the global number, the wallet is charged the regional one. Not latency — a permanent divergence for any region ops has customised.
2. **OP-02 · P1 · Pricing cache is per-pod, 60 s, unbustable.** Two pods ⇒ refresh the app and see old, new, old for a minute after saving `eur_per_bc`. `RegionsService` got a `refresh()`; `PricingService` never did, and B-721's "bust-on-mutation" covers `acct-gate` only.
3. **OP-04 · P1 · New regions are dead on arrival in the client.** Backend does the right thing (`ensureFresh()` on the availability call, explicitly "so it has to show a region the moment ops adds one"); the client throws the list away. Five compiled constants have to change → app build + store release.
4. **OP-03 · P2 · `tier-gate` has no bust.** Comp a user to Pro in ops → `/auth/me` says pro, `TierGuard` says `tier_insufficient` for ≤30 s → the app shows Pro chrome and the Pro action 403s. The file header claims every mutation busts; true for `acct-gate`, false for `tier-gate`.
5. **OP-05 · P2 · Regions cache is single-pod on refresh and never boot-loaded;** two agent-service validators skip `ensureFresh()` entirely.
6. **OP-06 · P2 · `acct-gate` is not busted on user suspend/restore or agent terminate** — a suspended user keeps passing the CPO session guard for ≤30 s.
7. **OP-08 · P3 · Client mirrors are mount-scoped and the auth snapshot is optimistic.** Pricing/catalog stores reload only when a screen MOUNTS (not on focus); `auth:user_snapshot` renders last session's tier/org/modules on cold boot for up to 4 s; foreground `/auth/me` is throttled to ≥30 s. A user sitting on a warm screen sees nothing change until they leave and return.
8. **OP-07 · P3 · Wallet adjust is silent** in both directions (no push; console card not mutated).
9. **OP-09 · P3 · Compliance decisions emit no push** and have no poll (agent approval has a 3 s poll; this surface got neither).
10. **Console-side: hidden tab = frozen console, no "last refreshed"** (OC-01 residual + OC-17, both still open — §5).

There is **no invalidation channel**: grep for `settings.changed|config.changed|pricing.changed|catalog.changed|tier.changed|emitToUser` across `apps/auth-service/src` returns zero. `auth-service` has no socket dependency at all; the only server→app wake is `BookingPushBridge` → FCM data message, used by booking/agent/pro flows only.
