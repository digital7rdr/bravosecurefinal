# Messaging + Calling — production-grade hardening audit (2026-09-02)

**Ask (founder):** "full phase audit on messaging and calling … it's now good but make it
production grade" + "you do the deployment".

**Method.** Six read-only auditors (inbound pipeline, outbound pipeline, notifications, 1:1
calls, group/SFU calls, chat UX + perceived performance) ran against HEAD `2138c639`, each
seeded with the fixed-bug baseline (B-692/703/710/712/715/717/718/726/727/728/731/732–738,
MESSAGE_LOOP M1–M16, CALL_RACE §13/§20/§21) so nothing already closed is re-reported. Every
finding below that is marked **fix** was then re-verified at source by the lead (file:line
re-read, not trusted from the report). Findings the lead could not confirm, or that are
product decisions rather than defects, are in §4 (backlog) and §5 (device-owed).

**Scope rule.** "Production grade" here means: no silent failures, no half-applied
destructive actions, no state that diverges between memory and disk, no dead recovery
lane, no synchronous mount of an unbounded list. WhatsApp feature parity (voice-note
player, media tabs, archive, mute durations, location) is recorded in §4 as a ranked
product backlog, not silently built.

**Status legend.** `FIXED` = shipped in this session's fix round (see sqa.md B-751…);
`OPEN` = recorded, not fixed (reason given); `ARCH` = needs an architecture decision
(privacy / wire / product rule) before anyone touches it.
